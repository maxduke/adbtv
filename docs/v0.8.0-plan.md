# ADB TV 0.8.0 Plan

Status: Defined

## Objective

Make the existing Android TV remote faster and more tactile without introducing a second remote layout or a general customization system.

## Confirmed Scope

- Keep the current D-pad as the primary navigation control.
- Do not add a touchpad mode.
- Do not add customizable buttons.
- Do not add an app launcher, pinned apps, or a new device dashboard.
- Keep live Device Information in Tools; do not add automatic dashboard queries.
- Reuse native text-field paste instead of adding a separate clipboard control.
- Repeat D-pad directions and volume up/down while their controls are held.
- Do not repeat media, select, back, home, menu, settings, mute, or power actions.
- Map external-keyboard arrows to D-pad directions, Return to Select, and Escape to Back.
- Do not add letter, media, Tab, Delete, or Space keyboard shortcuts.
- Follow native iOS repeat events for held external-keyboard arrows; keep Return and Escape one-shot.
- Serialize keyboard repeats and never enqueue catch-up actions.
- Produce one light haptic when an on-screen remote gesture begins and a warning haptic if its operation fails.
- Do not produce haptics for keyboard input or individual repeated events.
- Send a Repeating TV Remote Action immediately, wait 350 milliseconds, then repeat at most eight times per second.
- Serialize repeats and never enqueue catch-up actions when the TV or network is slower than the target rate.
- Stop a held operation after the existing eight-second remote-operation timeout.

## Interaction Contract

- A short press sends exactly one action even if the user releases before the TV acknowledges it.
- Releasing a held control prevents new sends; one already in flight may finish.
- Leaving Remote, backgrounding the app, explicit cancellation, timeout, or the first send failure stops the repeat operation.
- A repeat failure uses the existing User Error and Diagnostic Detail presentation.
- Only the control that owns the held gesture remains active; unrelated device actions stay unavailable until it finishes.
- Keyboard mappings are inactive while the text field owns keyboard focus.

## Implementation Approach

- Preserve the existing one-shot remote path for taps, Return, and Escape.
- Reuse one checked ADB connection for the duration of an on-screen held gesture.
- Add the minimum gesture state needed to distinguish press, hold, release, and cancellation; do not add a general input framework.
- Use native SwiftUI key press phases for external-keyboard arrows and accept native repeat events only when the previous send has completed.
- Use native iOS sensory feedback; do not add a haptics dependency or settings surface.
- Keep the existing Remote layout, labels, accessibility names, status, cancellation, timeout, and device-operation ownership.

## Automated Checks

- A short press sends once and release does not cancel its initial send.
- A held action sends immediately, waits 350 milliseconds, and remains serialized at no more than eight sends per second.
- Release, cancellation, failure, navigation, backgrounding, and timeout stop future sends without a catch-up queue.
- Only D-pad directions and volume up/down repeat.
- Arrow, Return, and Escape mappings produce the expected TV Remote Actions and do not intercept text-field input.
- Existing one-shot remote, text input, Unicode helper, media, and operation-ownership tests remain green.

## Physical Validation

- Hold each D-pad direction and volume control on at least one Android TV and confirm responsive movement without continued actions after release.
- Repeat against a slow or unreachable TV and confirm the operation remains cancellable and ends with bounded diagnostics.
- Verify arrow, Return, and Escape behavior with an external iPad or iPhone keyboard, including while the text field is focused.
- Confirm light touch-down haptics, failure warning haptics, VoiceOver labels, and portrait iPhone/iPad layouts.
