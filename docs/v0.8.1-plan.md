# ADB TV 0.8.1 Plan

Status: Released July 24, 2026

## Objective

Improve the stability, efficiency, accessibility, and visual consistency of
ADB TV without adding user-facing capabilities or changing its navigation.

## Audit Findings

- Reject inbound ADB packet payloads larger than the app's advertised 1 MiB
  limit before buffering their contents.
- Reflow media and Install controls at accessibility Dynamic Type sizes.
- Let Files and Tools icons use their natural accessibility size instead of
  overlapping adjacent labels.
- Keep navigation and production dependencies unchanged. Update the bundled
  helper only to restore app metadata on Android 8 after physical validation
  exposed an API 28-only version-code call.
- Android 10.0.0 and Android 8.0.0 physical testing passed. Android 8.0 app
  metadata required an API 26 version-code fallback and removal of the
  unsupported `head -c` response pipeline.
- Use a single-line ADB Shell command field so the keyboard's **Send** action
  runs the command instead of inserting a newline.
- Use the published `v0.8.0` IPA and its passing checksum, archive, CI, and
  portrait snapshots as the automated baseline.

## Confirmed Scope

- Treat `0.8.1` as a strict maintenance release after `0.8.0`.
- Add no new user-facing features.
- Preserve the current navigation and screen structure.
- Limit UI changes to local layout, consistency, and accessibility fixes.
- Continue supporting iPhone and iPad on iOS 17 or later.
- Preserve the current portrait-only orientation policy.
- Review reliability, lifecycle edge cases, accessibility, performance, and
  resource use.
- Refactor only to fix a concrete defect or a measured problem.
- Keep the bundled Android helper unchanged unless validation proves a defect
  originates in the helper.
- Keep production dependency versions unchanged unless a relevant security fix
  or confirmed compatibility defect requires an upgrade.
- Preserve the Bonjour capability gate and treat manual connection as the
  supported path for ordinary sideloaded builds.
- Make accessibility a release gate across Device Library, device detail,
  Remote, Apps and Install, Files, and Tools.
- Support every Dynamic Type size, including accessibility categories, by
  reflowing or scrolling where needed while preserving stable Remote controls.
- Verify VoiceOver labels and focus order, contrast, and minimum touch targets.
- Use native SwiftUI patterns and the existing visual language. Do not add a
  design system, decorative restructuring, or a UI dependency.
- Use local profiling and automated regression checks only. Add no analytics,
  telemetry, crash SDK, or production logging service.
- Compare performance with `v0.8.0` on the same Apple device and Android TV.
  Do not use arbitrary cross-device timing or memory limits.
- Preserve behavior already validated for `0.8.0`.

## Audit Sequence

### 1. Establish the baseline

- Run the Swift package tests, simulator build, and current portrait snapshot
  workflow from an unchanged `v0.8.0` build.
- Record repeatable observations for launch and idle, Remote readiness and
  input, app and file loading, cancellation, and memory after repeated work.
- Use the same iPhone, iPad, Android TV, network, and test data for candidate
  comparisons.

### 2. Review correctness and lifecycle behavior

- Trace every task, ADB connection, Remote Session, timeout, and cancellation
  path through foregrounding, backgrounding, navigation, device loss, retry,
  and late completion.
- Verify that a stale result cannot replace newer state and that an unreachable
  Saved Device never traps navigation or blocks later reconnection.
- Verify Saved Device persistence, Synced ADB Identity handling, helper
  compatibility, temporary-file cleanup, Package Manager session cleanup, and
  bounded shell, screenshot, archive, download, and file operations.
- Recheck confirmations and recovery for uninstall, force stop, cache cleanup,
  file mutation, arbitrary shell input, and insecure Install URLs.
- Preserve concise User Errors and copyable Diagnostic Detail.

### 3. Review UI and accessibility

- Inspect every primary screen on iPhone and iPad in light and dark appearance,
  at default and largest accessibility Dynamic Type sizes.
- Check intermediate Dynamic Type sizes when a layout changes between those
  boundaries.
- Verify VoiceOver labels, values, traits, focus order, and modal focus; minimum
  touch targets; contrast; text reflow; scrolling; and keyboard focus.
- Exercise loaded, empty, loading, cancelling, offline, failure, and recovery
  states without changing navigation or introducing decorative UI.
- Extend the existing manual snapshot workflow only where a discovered layout
  regression needs durable coverage.

### 4. Review performance and resources

- Confirm launch and idle do not start unavailable Bonjour work or retain an
  ADB connection.
- Compare Remote connection readiness, rapid input, held input, and cleanup
  with `v0.8.0`.
- Exercise large app and file listings, repeated screenshots, APK/APKM
  preparation, URL downloads, and file transfers while observing responsiveness
  and memory recovery.
- Optimize only a reproduced regression or clearly retained resource. Prefer a
  local fix and add the smallest regression check that proves it.

### 5. Prepare a candidate only when justified

- Keep fixes in small commits grouped by root cause.
- Do not perform a broad view decomposition, protocol rewrite, or speculative
  cleanup as part of a defect fix.
- Add or update tests and the existing hardware checklist for each behavior
  changed.
- Set version `0.8.1` and increment the build number only after at least one
  release-worthy fix exists.
- Run CI, portrait snapshots, unsigned IPA packaging, checksum validation, the
  physical-device matrix, and the in-place upgrade test before tagging.

## Release Blockers

- Crashes, hangs, data loss, or an incorrect destructive action.
- A broken primary workflow, cancellation path, or recovery path.
- An accessibility failure in a primary flow.
- A measurable regression from `0.8.0`.
- An in-place upgrade that loses Saved Devices, custom names, endpoints,
  pairing state, or Synced ADB Identity; breaks the installed helper; or
  unexpectedly requires pairing again.

Minor cosmetic findings may be documented and deferred when they do not affect
clarity, accessibility, or task completion.

If the review finds no concrete defect, accessibility failure, or measurable
regression, document the completed audit and do not publish `0.8.1`.

## Validation Matrix

- Run the existing hardware checklist across pairing, Device Library, Remote,
  Apps and Install, Files, Tools, settings, and upgrade behavior.
- Run the primary workflow and accessibility checks on a physical iPhone.
- Run the primary workflow and accessibility checks on a physical iPad.
- Run manual host/port connection and primary workflow checks against two
  physical Android TV devices.
- Record each TV model and exact Android version during validation. Do not add
  version-specific compatibility claims without that evidence.
- Keep simulator builds and Swift package tests green in CI.

## Out of Scope

- New device-management features or Remote controls.
- Touchpad mode, app launcher, customization, or navigation redesign.
- Bonjour workarounds for builds without Apple's required entitlement.
- Android helper changes without a reproduced helper defect.
- Routine dependency upgrades, telemetry, analytics, or production diagnostics.
- Broad refactors justified only by file size or code style.
