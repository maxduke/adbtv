# ADB TV 0.9.0 Plan

Status: Planning

## Release Intent

Let a user disable an unwanted Preinstalled App that consumes resources and
later restore it. Keep the workflow within the existing Apps area.

`0.9.0` remains one cohesive feature release rather than a collection of
unrelated tools or broad maintenance work.

## Scope Boundary

- Manage complete Preinstalled App packages.
- Preserve disabled packages so the user can enable them again.
- Do not expose Android receiver, service, provider, or activity component
  controls.
- Do not claim that ADB TV can determine whether every OEM package is safe to
  disable.

## Eligibility Policy

- Show all Preinstalled Apps.
- Prevent disabling packages that ADB TV identifies as Android framework,
  System UI, the active launcher, Settings, package installer, the active
  input method, or ADB TV Helper.
- Explain why the disable action is unavailable for a Protected Preinstalled
  App.
- Warn before disabling every other Preinstalled App.
- Treat protection as a guardrail. An unprotected package is not certified
  safe because OEM dependencies vary by device and firmware.

## Recovery

- Keep Disabled Preinstalled Apps in the existing System Apps list.
- Mark their state clearly and keep them discoverable through app search.
- Replace the disabled app's Disable action with Enable.
- Refresh the app's state after either action so the UI reflects the device
  rather than assuming the command succeeded.

## Decisions Pending

- Confirmation and failure behavior.
- How enabled and disabled states are loaded.
- Android-version and OEM compatibility boundaries.
- Automated and physical validation requirements.
