# ADB TV 0.9.0 Plan

Status: Ready for implementation

## Release Intent

Let a user disable an unwanted Preinstalled App that consumes resources and
later restore it. Keep the workflow within the existing Apps area.

`0.9.0` remains one cohesive feature release rather than a collection of
unrelated tools or broad maintenance work.

## Scope Boundary

- Manage complete Preinstalled App packages.
- Preserve disabled packages so the user can enable them again.
- Let the user choose packages; do not estimate resource consumption or
  recommend packages to disable.
- Do not expose Android receiver, service, provider, or activity component
  controls.
- Do not claim that ADB TV can determine whether every OEM package is safe to
  disable.

## Eligibility Policy

- Show all Preinstalled Apps.
- Prevent disabling packages that ADB TV identifies as Android framework,
  System UI, the active launcher, Settings, package installer, the active
  input method, or ADB TV Helper.
- Protect reviewed ecosystem infrastructure identifiers, including Google Play
  services, Google Services Framework, Play Store, and known OEM equivalents.
- Treat the reviewed identifier set as an additional guardrail rather than an
  exhaustive cross-OEM catalog.
- Explain why the disable action is unavailable for a Protected Preinstalled
  App.
- Warn before disabling every other Preinstalled App.
- Treat protection as a guardrail. An unprotected package is not certified
  safe because OEM dependencies vary by device and firmware.
- If any required protection check cannot identify its package, fail closed:
  disable every new Disable action and explain that safety checks are
  incomplete.
- Keep browsing, existing app-management actions, and Enable recovery
  available when protection checks are incomplete.

## Recovery

- Keep Disabled Preinstalled Apps in the existing System Apps list.
- Mark their state clearly and keep them discoverable through app search.
- Establish the Managed Disablement before sending the Disable operation, then
  present the package as disabled only after Android reports that state.
- Offer Enable only when Android reports the package disabled and it has a
  Managed Disablement for that Managed Device.
- Keep packages disabled by Android, the OEM, or another tool visible, but do
  not offer to enable them.
- Remove the Managed Disablement only after Android reports and ADB TV verifies
  that the package returned to its default state.
- Refresh the app's state after either action so the UI reflects the device
  rather than assuming the command succeeded.
- When deleting a Saved Device with Managed Disablements, require confirmation
  and offer Review Disabled Apps before removal.
- Review Disabled Apps opens the existing System Apps list filtered to that
  device's Managed Disablements.
- Restore each package separately through the normal Enable action; do not add
  an Enable All operation.
- Keep Remove Anyway available for an unreachable TV, with an explicit warning
  that ADB TV will lose its recovery records.
- Never discard Managed Disablements through an unconfirmed device deletion.

## Confirmation

- Require a destructive confirmation before disabling an eligible
  Preinstalled App.
- Show its display name and package identifier.
- Warn that ADB TV cannot know every OEM dependency and that disabling the app
  may remove TV features or affect other apps.
- Explain that the package remains installed and can be enabled again from the
  same System Apps entry.
- Enabling an app does not require destructive confirmation.

## Presentation

- Keep disable and enable controls in the Preinstalled App detail screen.
- Add one compact System Control section containing the package state,
  protection or recovery explanation, and the available action.
- Mark disabled packages in System Apps rows so their state remains scannable.
- Do not add disable actions to list rows, swipe actions, or context menus.
- Reuse the existing app-detail layout and destructive confirmation style.

## Operation Model

- Disable or enable one Preinstalled App at a time.
- Apply the change only to the active Android user and do not expose a user
  selector.
- Resolve and retain the numeric Android user ID so recovery cannot affect a
  different profile if the TV's active user later changes.
- Disable additional app actions while the package state change is running.
- Verify the package's reported state after the command completes.
- Do not add selection mode, batch operations, or partial-batch recovery.

## Persistence

- Store Managed Disablements with their Saved Device in the existing local
  Device Library.
- Preserve them across app restarts, device renames, and connection updates.
- Decode existing Saved Devices without this new data as having no Managed
  Disablements.
- Persist recovery authority before sending the disable command. Refuse to
  disable the package if that save fails.
- Reconcile the durable record with Android's reported package state after the
  operation and whenever System Apps reload.
- Remove a stale record when Android reports the package enabled.
- Keep the record when the remote outcome is disabled or cannot be determined,
  so recovery remains available.
- Do not add helper storage or cloud synchronization.

## Failure Behavior

- Treat Android's queried package state as authoritative when it can be read,
  even if the preceding command returned an unusual result.
- When the resulting state cannot be verified, show State Not Confirmed and do
  not claim success.
- Retain recovery authority after an unconfirmed Disable outcome.
- Provide Check Again instead of automatic retries.
- Keep the existing User Error and expandable Diagnostic Detail presentation.
- Reconcile state after cancellation, timeout, disconnect, app interruption,
  or the next System Apps reload.

## Native Android Operations

- Load the active numeric user with `am get-current-user`.
- Load Preinstalled Apps with
  `pm list packages -s --user <user-id>`.
- Load their effective disabled state with
  `pm list packages -s -d --user <user-id>`.
- Build protection reasons from validated package identifiers returned by
  HOME, Settings, and package-installer intent resolution; the active input
  method; the fixed Android and System UI packages; ADB TV Helper; and the
  reviewed ecosystem-infrastructure set.
- Disable with
  `pm disable-user --user <user-id> <package>`.
- Restore with
  `pm default-state --user <user-id> <package>`. Do not force `enable`, because
  restoration must remove ADB TV's override and respect the package's default.
- Query the disabled set again after every state-changing command.
- Validate every user ID, package name, component name, command exit status,
  and bounded response before it reaches presentation state.

System-app state and protection use these native shell queries. Optional helper
metadata remains a separate best-effort load for names, versions, sizes, and
icons.

## App Integration

1. Extend `ADBTVInstalledAppManager` with the smallest snapshot and
   state-change APIs needed by the existing installed-app command flow.
2. Extend `ADBTVDeviceSummary` with bounded Managed Disablements keyed by
   numeric Android user ID and package name.
3. Preserve that data when an existing endpoint is verified, renamed, or
   repaired; the current replacement paths must not overwrite it.
4. Save recovery authority before starting Disable. If persistence fails,
   leave Android unchanged and show the existing Device Library error.
5. Reconcile and persist after Disable, Enable, Check Again, cancellation, and
   every System Apps load.
6. Add disabled state to System Apps rows and one System Control section to the
   existing app-detail sheet.
7. Intercept deletion of any Saved Device with Managed Disablements. Review
   selects and reconnects that device, then opens System Apps filtered to its
   recovery entries. Remove Anyway uses an explicit destructive confirmation.

Do not add a new manager layer, helper API, background monitor, or production
dependency.

## State Presentation

- **Enabled**: show Disable only for an eligible, unprotected Preinstalled App
  after all safety checks succeed.
- **Protected**: show the protection reason and no Disable action.
- **Disabled by ADB TV**: show Enable and retain the Managed Disablement until
  default state is verified.
- **Disabled elsewhere**: show Disabled with an explanation and no Enable
  action.
- **State not confirmed**: retain recovery authority, show Check Again, and
  expose Diagnostic Detail.
- **Safety checks incomplete**: keep app browsing and Enable recovery
  available while disabling all new Disable actions.

Launch and Force Stop must be unavailable for an effectively disabled package.

## Compatibility

- Keep Android 8.0 (API 26) as the compatibility floor.
- Android 8 provides the required numeric current-user query, package filters,
  intent resolution, `disable-user`, and `default-state` commands.
- Use numeric user IDs because Android 8's legacy `pm disable-user --user`
  parser does not accept `current`.
- Treat malformed output, missing role resolution, rejected shell permission,
  or OEM command divergence as incomplete safety checks and fail closed.
- Require no Android Helper installation for package state or controls.
- Make no compatibility claim below Android 8 or for rooted/vendor-modified
  package managers without physical evidence.

## Automated Validation

- Package and component validation rejects shell metacharacters, malformed
  output, duplicate entries, invalid user IDs, and oversized responses.
- Snapshot tests cover enabled, protected, Managed Disablement, externally
  disabled, incomplete-safety, and missing-package states.
- Command tests verify numeric user scoping, `disable-user`, `default-state`,
  checked exit status, and authoritative post-command queries.
- Device-model tests cover Codable migration, corrupt recovery records,
  persistence round trips, rename, endpoint refresh, connection repair, and
  Remove Anyway.
- Operation tests cover save-before-disable, save failure, cancellation,
  timeout, disconnect, unusual command output, state mismatch, and Check Again.
- UI snapshot coverage includes long package identifiers, missing helper
  metadata, every System Control state, confirmation text, Dynamic Type, dark
  appearance, and narrow iPhone layouts.
- Run the existing Swift package CI, iOS build, and UI snapshot workflows.

## Physical Validation

- On Android 8.0 and Android 10.0 hardware, disable one known non-critical
  Preinstalled App, confirm it cannot launch, reboot the TV, and verify the
  disabled state and recovery entry persist.
- Restore it, verify the package returns to default state, and confirm its app
  data remains intact.
- Verify Android framework, System UI, active launcher, Settings, package
  installer, active input method, helper, and recognized ecosystem
  infrastructure are protected with understandable reasons.
- Verify an OEM-disabled package cannot be enabled.
- Repeat with the Android Helper absent.
- Interrupt or disconnect during Disable, reconnect, and confirm Check Again
  reconciles the real device state without losing recovery authority.
- Rename and update the device connection, then confirm recovery entries remain.
- Attempt device deletion with recovery entries, exercise Review Disabled Apps,
  and verify Remove Anyway requires explicit confirmation.
